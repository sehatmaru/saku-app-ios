# Saku iOS

Saku is a personal finance app for iPhone, written in Indonesian first with an English translation. It tracks
wallets, transactions, budgets, credit card bills and investment wallets, and it can log spending for you from
a typed sentence, a bank notification, a receipt photo or a forwarded email (Smart Tracker).

SwiftUI, iOS 18, Swift 6. Backend on Supabase. Project file generated by XcodeGen.

## What is in the app

| Area | Folder under `App/Features/` |
|---|---|
| Sign in, guest mode, link Google, delete account | `Authentication`, `Profile` |
| Wallets, credit cards, investment wallets | `Accounts` |
| Transactions and categories | `Transactions`, `Categories` |
| Budgets | `Budgets` |
| Home, statistics, period analysis | `Dashboard` |
| Smart Tracker (typed text, notifications, photos, drafts) | `SmartTracker` |
| CSV and PDF export | `Export` |
| Saku Plus, free limits, AI quota, referral | `Plus` |

Free plan limits and Saku Plus rules live in `App/Models/FreeLimits.swift` and `App/Models/Entitlement.swift`.
The share extension is in `Extensions/Share`.

## Layout

```text
App/
  Core/            app-wide helpers
  Features/        one folder per area above (Views and ViewModels)
  Models/          plain value types and the logic on them (balances, periods, limits, Plus status)
  Services/        Supabase client and data access, notifications, StoreKit purchases, Smart Tracker drafts
  Repositories/    reserved, currently empty
  Shared/          reusable views and utilities
  Resources/       Info.plist, assets, Localizable.xcstrings
Extensions/Share/  share extension
Tests/             unit tests (Tests/UI holds the UI tests)
Docs/              translation sources and the catalog builder
Supabase/          migrations and Edge Functions (kept local, not in git)
project.yml        XcodeGen definition: the .xcodeproj is generated from it
PRD.md             product requirements
```

## Getting started

Requirements: Xcode 16 or newer, [XcodeGen](https://github.com/yonaskolb/XcodeGen), Python 3.

```sh
xcodegen generate          # run again after adding or removing Swift files
open Saku.xcodeproj
```

Pick the `Saku` scheme and run. Swift packages (supabase-swift, GoogleSignIn) resolve on first open.
The Supabase project URL and public key are set in `App/Services/SupabaseSDK.swift`; ask the owner for access to the project.

To run on a device, build with your own team:

```sh
xcodebuild -scheme Saku -destination id=<device UDID> -allowProvisioningUpdates DEVELOPMENT_TEAM=<team id> build
xcrun devicectl device install app --device <device UDID> <path to Saku.app>
```

## Tests

```sh
xcodebuild -scheme Saku -destination 'platform=iOS Simulator,name=<simulator>' test -only-testing:SakuTests
```

`SakuTests` is the fast unit suite. The UI tests in `Tests/UI` are slow and are not part of the daily loop.
Saku Plus purchase tests use the local StoreKit configuration `Tests/Saku.storekit`, which the `Saku` scheme also
uses when you run from Xcode, so purchases can be tried without an App Store Connect account.

## Localization

Indonesian text in the code is the key. Use `Text("...")`, `L("...")` or `Lx(id, en:)`; `Text(someString)` is not
translated, so wrap it as `Text(L(someString))`.

1. Add the English text for every new string to `Docs/en_part6.json` (check the other `en_part*.json` for duplicates first).
2. Run `python3 Docs/build_catalog.py` to rebuild `App/Resources/Localizable.xcstrings`.

Xcode rewrites the catalog on every build, so check that the key count did not drop and rerun the script if it did.

## Backend

Migrations are plain SQL files in `Supabase/migrations/` and are run by the owner by hand. Edge Functions are in
`Supabase/functions/`:

- `smart-parse`: AI parsing for Smart Tracker (needs `ANTHROPIC_API_KEY`; until it is deployed the on-device parser is used).
- `purge-accounts`: daily job that permanently deletes accounts after their 30 day wait.
- `apple-iap`: receives App Store purchases and server notifications and sets the Plus status.
  Deploy with `supabase functions deploy apple-iap --no-verify-jwt`.

## Saku Plus and the test switch

Purchases go through StoreKit 2 (`App/Services/PlusPurchases.swift`) with the temporary product ids
`id.saku.plus.monthly` and `id.saku.plus.yearly`. Debug and TestFlight builds also show an internal switch under
Profil, Paket Saku that sets every Plus state without buying. It must be turned off before an App Store release
(`app_flags.test_plus_switch`).
